## Reading the numbers

* -25 → -50 mV: +4.8 % generation throughput at the same power. This is
  the whole gain.
* -50 → -75 → -100 mV: flat. The card is power-capped at 210 W, and past
  -50 mV the extra voltage headroom no longer converts to clock; the
  differences (0.2 tok/s) are inside the run-to-run noise measured
  earlier (two -25 mV runs agreed within 1 %).
* Junction temperature climbs monotonically (75 → 83 °C) but the steps
  ran back to back with only ~20 s of D3cold between them, so thermal
  history is confounded with the offset. Do not read the Tj column as
  "deeper undervolt runs hotter" without a repeat in random order with a
  cool-down between steps.
* No instability was observed down to -100 mV under this workload. That
  is one workload, one run each, ~80 s of steady state per point. It is
  not a stability proof.

## Decision

* Safe point restored to **-25 mV / 210 W** immediately after the run
  (the stepping script leaves the last tested value in the config by
  design; the owner approved the test, not a new daily setting).
* Recommendation: adopt **-50 mV / 210 W** as the daily setting. It
  captures the entire measured gain with the shallowest offset.
  -75/-100 mV buy nothing at this cap and reduce margin for no return.
* Not done: caps other than 210 W, repeats, randomised order, longer
  soak, other workloads. See ROADMAP.

## Script fixes made for this run

* Daemon CLI calls go through `sudo -n` when the script is not root, so
  the operator's narrow sudoers rule is enough.
* Readback verification understands a suspended card: the daemon
  validates against the cached ranges and writes the config; the
  watcher applies on wake, and a new gate checks that the harness's
  post-warm-up live reading equals the target.
